Se você já possui um fork deste repositório, atualize-o antes de começar a tarefa:

1.  Entre na pasta do repositório clonado.
2.  Adicione o repositório original como `upstream` (se ainda não existir):
    ```bash
    git remote add upstream https://github.com/seu-usuario/repo.git
    ```
3.  Atualize o fork com os commits mais recentes:
    ```bash
    git fetch upstream
    git checkout main
    git merge upstream/main
    ```
4.  Envie as alterações para o seu fork:
    ```bash
    git push origin main
    ```

## Questão 1: Conceitos de CI/CD (Teórica)

a) **CI (Continuous Integration):**

O objetivo principal da CI é **integrar código com frequência** (commits/merges), executando validações automáticas para detectar falhas cedo. Nessa fase, o código passa por etapas como lint, testes automatizados e build da aplicação/imagem Docker, gerando feedback rápido para o time.

b) **CD (Continuous Delivery/Deployment):**

O objetivo principal da CD é **entregar o artefato buildado de forma automática e confiável** para ambientes de destino.

- Em **Continuous Delivery**, o artefato fica pronto para produção, mas a liberação final pode exigir aprovação manual.
- Em **Continuous Deployment**, após passar nos gates de qualidade, o deploy em produção ocorre automaticamente.

## Questão 3: Amazon ECR (Teórica)

a) **Vantagem principal do ECR vs Docker Hub público (segurança e privacidade):**

O ECR oferece repositório **privado e integrado ao IAM da AWS**, permitindo controle fino de acesso por usuário/role/política, integração com auditoria (CloudTrail), e menor exposição de imagens internas da organização.

b) **Escopo do serviço e formato do URI:**

O ECR é um serviço **regional**.

Formato padrão do URI:

`<aws_account_id>.dkr.ecr.<aws_region>.amazonaws.com/<repository_name>`

Exemplo:

`123456789012.dkr.ecr.us-east-1.amazonaws.com/web-app-repo`

## Questão 4: Processo de Push (Prática Teórica)

Sequência correta para enviar imagem local ao ECR:

1. **Passo de Autenticação (AWS CLI + Docker CLI):**
    Gerar senha temporária com AWS CLI e autenticar no registry com Docker.

2. **Passo de Tagging (Docker CLI):**
    Marcar a imagem local com o URI completo do ECR e a tag desejada.

3. **Passo de Upload (Docker CLI):**
    Executar o push da imagem tagueada para o repositório remoto.

## Questão 5: Tarefa Prática Integrada (Simulação com AWS CLI e Docker)

Valores fornecidos:

- AWS_ACCOUNT_ID=123456789012
- AWS_REGION=us-east-1
- REPO_NAME=web-app-repo
- IMAGEM_LOCAL=web-app:v1

a) **Criação do repositório (aws ecr):**

```bash
aws ecr create-repository \
  --repository-name web-app-repo \
  --region us-east-1
```

b) **Autenticação Docker no ECR:**

```bash
aws ecr get-login-password --region us-east-1 | \
docker login --username AWS --password-stdin 123456789012.dkr.ecr.us-east-1.amazonaws.com
```

c) **Tagging da imagem local:**

```bash
docker tag web-app:v1 123456789012.dkr.ecr.us-east-1.amazonaws.com/web-app-repo:v1
```

d) **Push final:**

```bash
docker push 123456789012.dkr.ecr.us-east-1.amazonaws.com/web-app-repo:v1
```
