## Questão 1: Três Pilares da Observabilidade (Teórica)
A observabilidade moderna se baseia em três pilares fundamentais.

a) Quais são os **três pilares da observabilidade** e qual é o objetivo específico de cada um?

b) No contexto do EKS na AWS, qual serviço/ferramenta é responsável por cada pilar?

c) Explique a diferença entre **monitoramento** e **observabilidade**. Por que apenas monitorar não é suficiente?

## Questão 2: CloudWatch Logs e Fluent Bit (Teórica)
A coleta de logs é crucial para debugging e auditoria de aplicações containerizadas.

a) O que é o **Fluent Bit** e por que ele é deployado como **DaemonSet** no EKS? O que um DaemonSet garante?

b) Explique a diferença entre **Log Group** e **Log Stream** no CloudWatch Logs.

c) Por que é importante configurar uma **política de retenção** nos Log Groups? O que acontece se não configurar?

## Questão 3: Container Insights e Métricas (Teórica)
O Container Insights fornece métricas avançadas para clusters EKS.

a) Qual é a diferença entre as métricas **padrão do EKS** e as métricas do **Container Insights**? Que informações extras o Container Insights fornece?

b) Explique o que é o namespace de métricas `ContainerInsights` no CloudWatch e que tipo de dados ele armazena.

c) O que o comando `kubectl top pods` mostra e por que ele é útil para monitoramento em tempo real?

## Questão 4: CloudWatch Alarms e Alertas (Teórica)

c) O que é um **alerta acionável** vs um **alerta genérico**? Dê um exemplo de cada.

## Questão 5: Tarefa Prática - Configuração de Monitoramento (Simulação)

## Questão 6: Evidências Práticas da Execução do Lab014
Você deve executar as etapas do arquivo `Aula 014/Lab014.md` e coletar evidências claras da execução.

### Parte 1: Preparação e Logs
Forneça prints ou capturas de terminal de:

1. **Cluster ativo:** `aws eks describe-cluster --name cluster-eks-ads --query 'cluster.status'` retornando `"ACTIVE"`.
2. **Log Group criado:** `aws logs describe-log-groups --log-group-name-prefix "/aws/eks/cluster-eks-ads"` mostrando o log group.
3. **Fluent Bit rodando:** `kubectl get pods -n amazon-cloudwatch` mostrando pods Fluent Bit em status `Running` (um por node).
4. **Logs no CloudWatch:** saída de `aws logs filter-log-events` mostrando eventos coletados.

### Parte 2: Métricas e Container Insights
Forneça prints ou capturas de terminal de:

1. **Container Insights habilitado:** evidência de que o addon ou DaemonSet foi instalado com sucesso.
2. **Métricas disponíveis:** saída de `aws cloudwatch list-metrics --namespace ContainerInsights` mostrando métricas do cluster.
3. **kubectl top:** saída de `kubectl top pods -n ads-unifaat` e `kubectl top nodes` mostrando uso de recursos.

### Parte 3: Alarmes e Dashboard
Forneça prints ou capturas de terminal de:

1. **Alarmes criados:** saída de `aws cloudwatch describe-alarms --alarm-name-prefix "EKS-ADS"` mostrando os 3 alarmes em estado `OK`.
2. **Dashboard criado:** evidência do dashboard via CLI ou screenshot do Console AWS mostrando os gráficos de CPU e Memória.

### Parte 4: Tráfego e Observação
Forneça prints ou capturas de terminal de:

1. **Geração de tráfego:** execução do script de load test ou loop de requisições.
2. **Métricas reagindo:** saída de `kubectl top pods` durante ou após a carga, mostrando aumento de uso.
3. **Logs de acesso:** `kubectl logs -n ads-unifaat -l app=ads-site --tail=10` mostrando requisições registradas.

### Parte 5: Limpeza
Forneça prints ou capturas de terminal de:

1. **Alarmes removidos:** confirmação de `aws cloudwatch delete-alarms`.
2. **Log Groups removidos:** confirmação de `aws logs delete-log-group`.
3. **Namespace removido:** `kubectl delete namespace amazon-cloudwatch`.

## Como atualizar o fork feito anteriormente
Se você já possui um fork deste repositório, atualize-o antes de começar a tarefa:

1. Entre na pasta do repositório clonado.
2. Adicione o repositório original como `upstream` (se ainda não existir):
    ```bash
    git remote add upstream https://github.com/professor-ale/unifaat_implantacao_servidores-202601.git
    ```
3. Atualize o fork com os commits mais recentes:
    ```bash
    git fetch upstream
    git checkout main
    git merge upstream/main
    ```
4. Envie as alterações para o seu fork:
    ```bash
    git push origin main
    ```

> Após isso, crie a pasta do seu RA em `Aula 014`, adicione os arquivos e abra o pull request com o padrão de título exigido.
